Memory should have paths, not piles

Integ.Life Memory now combines an Inbox with Markdown file paths and collapsible folders, so notes can gain structure without slowing down capture.

notesmemoryworkfloworganization
中文

This is part one of a four-part update on the current Integ.Life workflow.

The fastest way to make a note system unusable is to demand perfect organization at capture time. A thought arrives, but before saving it you have to choose a notebook, invent a category, and decide where it belongs. The structure meant to help becomes a reason not to write.

The opposite extreme is not much better. If everything lands in one endless list, capture stays easy but retrieval slowly gets harder. The real question is how a system can begin loose and become structured only when the material earns it.

Inbox first, paths later

Integ.Life Memory now supports Markdown file paths and folder browsing. Existing notes remain available in Inbox, while notes that need a durable home can move into paths such as:

  • projects/blog/analytics.md
  • areas/health/sleep-notes.md
  • people/alex/follow-ups.md
  • archive/2026/q2-review.md

The path is not just decoration. It gives a note a place in a larger body of work. The same note can still use tags for cross-cutting topics, while folders answer the simpler question: where does this belong?

A tree should reduce scanning

Folders only help if browsing them is calmer than browsing the original pile. The latest Memory view lets folders expand and collapse, so a large collection does not have to remain visually open all at once.

That changes the role of the tree. It is not a complete map that must always be displayed. It is a working outline: open the project you are advancing, keep unrelated areas folded, and return to Inbox when you need to process new material.

Organize at the moment of reuse

My preferred rule is simple: capture without friction, organize when a note becomes useful for the second time.

A fleeting thought can stay in Inbox. A note that becomes part of an active project receives a path. A finished project can move under Archive without changing the note format or breaking the wider Memory model.

This keeps organization proportional to value. The system does not ask every fragment to predict its future. It waits until reuse provides evidence about where the note belongs.

Structure without losing continuity

Integ.Life started with notes because notes preserve context better than isolated commands. Folders do not replace that principle. They make it possible for the context to grow.

The useful sequence is still: capture a fragment, develop it, turn clear next steps into todos, and keep the source material available. Paths simply ensure that, months later, the reasoning can still be found beside the work it belongs to.
