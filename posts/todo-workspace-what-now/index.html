A todo workspace should answer: what now?

The current Integ.Life Todo workspace separates Today, Tomorrow, This week, Overdue, and MIT so a large task system can still produce a clear next move.

todosfocusplanningMIT
中文

This is part two of a four-part update on the current Integ.Life workflow.

A task system can contain everything and still fail at the moment that matters. You open it at 9:00, see dozens of items, and still do not know what to begin.

Storage and decision-making are different jobs. Collections and lists preserve the shape of projects. A working view should reduce that stored complexity into an answer for the current horizon.

Five views, five decisions

The current desktop Todo workspace offers focused views for Today, Tomorrow, This week, Overdue, and MIT.

  • Today is the commitment surface. It should stay small enough to trust.
  • Tomorrow is a pressure-release valve. Work can be scheduled without pretending it belongs today.
  • This week shows the near horizon before it turns into urgency.
  • Overdue is a negotiation queue, not a wall of shame. Each item needs a new date, a smaller next step, or deletion.
  • MIT keeps the most important task visible when everything else competes for attention.

The same underlying todo can move between these decision contexts without losing its collection, list, subtodos, or history.

Search should understand nested work

Large tasks are rarely flat. A project-level todo may contain several subtodos, and the useful phrase you remember may live inside one of them.

Nested task search makes the workspace behave more like a real outline. You can search for the remembered detail and still recover the parent context instead of treating every row as an unrelated item.

Details should not change with the layout

Task systems become frustrating when a quick side panel offers only half the actions available on a full page. Integ.Life now keeps the complete editing, subtodo, Pomodoro, and AI actions available in both contexts.

That consistency matters because attention is fragile. Opening a task from Today should not force a navigation detour just to start focus, add a child step, or clarify the work.

MIT is a constraint, not a badge

Marking a Most Important Task is useful only if it changes behavior. The point is not to decorate several tasks with another priority label. It is to make one trade-off explicit: if the day becomes noisy, which outcome should still move?

Once selected, the MIT can be paired with a Pomodoro session. The workspace answers what now; the timer records whether attention actually followed the decision.

This is where planning becomes evidence. At review time, the question is no longer only “Did I check it off?” It can also be “Did the work I called important receive focused time?”
